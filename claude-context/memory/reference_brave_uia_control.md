Soumil's Brave (C:\Users\soumi\Brave\Application\brave.exe, see [[reference_laptop_quirks]]) has no Claude browser extension; the Claude in Chrome connection called "Browser 1" is his Chrome, not Brave. To see what is on his Brave screen, run C:\cca\tools\brave_uia.ps1 with `powershell -NoProfile -ExecutionPolicy Bypass -File ... -Do "step;step"`. It needs no focus and no mouse. Steps: `dump` (sidebar and top bar), `dumplinks:<regex>` (clickable items matching a regex), `invoke:<name>` (click a link or button by its name), `invokeat:x,y` (click the element at window pixels, for unnamed icons), `setvalue:<text>` (fill the first edit field below the toolbar, used for the Miva Ctrl K search), `selecttab:<regex>`, `wait:<s>`, `shot:<file>`, `shotp:<file>` (page, half size), `shotc:<file>` (centre overlay), `shotr:<file>,x,y,w,h,scale`. Captures use PrintWindow and go to %TEMP%\brave_shots. Write such scripts with the Write tool, not shell heredocs.

**Why:** on 5 Oct 2026 he asked whether I could see the Miva admin settings in Brave; this read his logged-in session without touching history or credentials, and showed that his login has no Settings section (see [[client_lotus_sculpture]]).

**How to apply:** open only the tabs he asked about, and only navigate and read (never Add, Save, Delete, Sign Out, Publish). The Miva admin URL has no session id (cookie login); never print query strings. Miva global search for "orders" or "api" returns customer emails, so crop screenshots away from lists and delete any capture that shows customer data (NDA SG-LS-NDA-01 section 06); I deleted two on 5 Oct 2026. The tool switches the active Brave tab, so tell him.
More actions added 2026-10-06: `invokeany:<exact name>` (click any named link or button), `setvaluein:<field name>|<text>`, `key:{ENTER}` or `{ESC}` (needs Brave to win the foreground; Windows sometimes refuses, then nothing is sent), `clickxy:x,y` (real mouse click at window pixels, restores cursor and focus). Pitfalls: Miva's table rows are ONE merged link whose centre is not the link text; AutomationElement.FromPoint is polluted by the hidden Miva AI chat panel, so do not use `invokeat` there; clicking a report name in Analytics > Reports opens its Edit dialog (Save and Delete buttons), use `invokeany:Cancel` to leave. Page text dumps of Home or Orders show customer names: use `Showing`-style targeted lookups instead.
Learned 2026-10-06 (Kyle picture deck): READ THIS NOTE BEFORE using the driver, I re-discovered the table and Edit-dialog pitfalls the hard way. New variant C:\cca\tools\brave_uia_hold.ps1 (same steps plus): `pclick:x,y` = click by posting window messages straight to Brave's page widget, no physical mouse and no focus change; it worked on a Miva table row where nothing else did, and it is the ONLY click to use while Soumil is at the machine. `clickxy`/`clicktext`/`mclick` use the real cursor; his own mouse moved the pointer between my SetCursorPos and the click (read back 1121,626 then 2220,648), so those clicks landed in random places (only text selections happened, but never rely on them). Flow that worked with pclick only (no keys, no mouse): invoke:Orders, pclick the sliders icon inside Search Orders, Advanced Search, Date select, Between, Start field, picker (prev arrow, day, AM/PM toggle, Done), End field, Search; the list footer Showing 1-8 of N gives N. NEVER press keys on the Orders list: {ENTER} selected a row and opened a bulk-edit bar (Cancel is safe, Create Batch and Save Changes are not). Window handling: if Brave is minimized, `show` puts it back full-size on top WITHOUT taking focus, then `unpark` re-minimizes it from the saved placement; `park` (off-screen) does NOT work because the page thinks it is hidden and stalls. A restored tab may stay blank until `reload`. pclick targets the visible Chrome_RenderWidgetHostHWND (one per tab); `tclick` posts to the top-level window instead.
